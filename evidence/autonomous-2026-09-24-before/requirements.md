# 소비 위치 기록 지도 기반 가계부 요구사항

> 현재 상태 안내(2026-09-23): 이 문서의 승인 계약은 유지합니다. Windows 미실행·예정·당시 상태 문구는 작성 시점의 이력이며, 현재 구현/검증 상태와 누락은 [자체 점검](self-review.md)을 따릅니다. 핵심 구현은 있으나 개발·검증 미완료이며 배포만 남은 상태가 아닙니다.

## 1. 문서 목적과 범위

이 문서는 소비 위치 기록 지도 기반 가계부의 MVP 요구사항을 구현 가능한 수준으로 정의한다. 설계, 개발, 테스트 단계는 이 문서의 요구사항 ID와 완료 조건을 기준으로 추적한다.

이 문서는 다음 범위를 다룬다.

- 회원가입, 로그인, 로그아웃과 사용자 데이터 격리
- 수입 및 지출 거래의 등록, 조회, 수정, 삭제
- 거래별 선택적 위치 저장
- 지도에서 기간, 카테고리, 영역을 기준으로 소비 조회
- 장소, 지역, 카테고리, 기간별 소비 통계와 월별 비교
- 모바일 중심 화면 구조와 정상, 로딩, 빈 상태, 오류 상태
- 보안, 개인정보, 성능, 접근성, 호환성, 테스트 가능성 기준
- MVP, 후속 버전, 제외 범위 및 승인된 기본값

## 2. 시스템 개요와 핵심 가치

### 2.1 시스템 개요

사용자는 모바일 웹에서 수입과 지출을 기록한다. 지출을 등록할 때 위치를 저장하지 않거나, 현재 위치를 사용하거나, 장소를 검색하거나, 지도에서 지점을 직접 선택할 수 있다. 위치가 저장된 지출은 지도와 통계에서 장소 및 지역별 소비 패턴으로 확인할 수 있다.

### 2.2 핵심 가치

- 위치 입력을 강제하지 않아 일반 가계부처럼 빠르게 기록할 수 있다.
- 사용자가 어디에서 얼마를 소비했는지 지도에서 직관적으로 확인할 수 있다.
- 장소, 지역, 카테고리, 기간을 조합해 소비 패턴을 비교할 수 있다.
- 위치 권한 거부나 지도 연동 실패가 거래 기록 자체를 막지 않는다.

### 2.3 성공 조건

- 신규 사용자가 모바일에서 3분 이내에 가입하고 첫 지출을 등록할 수 있다.
- 재방문 사용자가 위치 없이 지출을 등록하는 핵심 흐름을 30초 이내에 완료할 수 있다.
- 위치가 있는 지출은 저장 직후 지도와 관련 통계에 일관되게 반영된다.
- 위치 권한 거부, 지도 키 미설정, 네트워크 오류가 발생해도 위치 없이 거래를 저장할 수 있다.
- 한 사용자는 다른 사용자의 거래, 위치, 통계, 카테고리를 조회하거나 변경할 수 없다.

## 3. 사용자 유형 환경 목표

### 3.1 주요 사용자

개인 소비를 기록하고 장소 및 지역별 소비 습관을 파악하려는 단일 개인 사용자다. 한 계정을 여러 사람이 공유하는 가구부 기능은 MVP에서 제공하지 않는다.

### 3.2 사용 환경

- 주 사용 환경: Android Chrome과 iOS Safari의 모바일 웹
- 보조 사용 환경: 최신 Chrome, Edge, Safari 데스크톱 브라우저
- 네트워크: 일반 Wi-Fi 또는 이동통신망
- 위치 기능: HTTPS 환경 및 브라우저 위치 권한이 필요함
- 지도 기능: Kakao Maps JavaScript API 사용 가능 환경이 필요함

### 3.3 사용자가 해결하려는 문제

- 거래를 기록해도 소비 장소와 지역 분포를 다시 파악하기 어렵다.
- 특정 장소에서 누적 지출한 금액을 계산하려면 거래를 수동으로 모아야 한다.
- 집 주변, 회사 주변 또는 특정 지역의 소비를 비교하기 어렵다.
- 지난달과 이번 달의 소비 지역 변화를 직관적으로 확인하기 어렵다.

### 3.4 모바일 핵심 작업

1. 로그인한다.
2. 금액, 카테고리, 날짜를 입력해 지출을 빠르게 등록한다.
3. 필요할 때만 위치 입력 방식을 선택한다.
4. 거래 내역을 조회하고 수정하거나 삭제한다.
5. 지도에서 소비 위치를 탐색한다.
6. 기간, 카테고리, 장소, 지역별 통계를 확인한다.

### 3.5 서비스가 하지 않을 일

- 사용자의 백그라운드 위치를 추적하거나 이동 이력을 자동 수집하지 않는다.
- 카드사, 은행, 문자 메시지에서 거래를 자동 수집하지 않는다.
- 회계, 세무 신고 또는 투자 자문 기능을 제공하지 않는다.
- 다른 사용자의 위치나 소비 정보를 공개하거나 소셜 기능에 사용하지 않는다.
- 영수증 OCR, AI 추천, 알림, 관리자 콘솔을 MVP에 포함하지 않는다.

## 4. 용어 정의

| 용어 | 정의 |
|---|---|
| 거래 | 사용자가 기록한 수입 또는 지출 데이터 |
| 거래일 | 실제 수입 또는 지출이 발생한 사용자의 달력 날짜 |
| 기록 시각 | 서버가 거래 레코드를 최초 저장한 시각 |
| 지출 위치 | 거래에 선택적으로 연결된 장소명, 주소 스냅샷, 좌표 및 출처 정보 |
| 장소 | 사용자가 소비한 구체적 지점. 검색 결과의 매장이나 지도에서 선택한 좌표 등을 포함 |
| 지역 | 주소 또는 좌표로 판정한 행정구역 집계 단위 |
| 위치 출처 | 없음, 현재 위치, 장소 검색, 지도 직접 선택 중 하나 |
| 지도 영역 | 현재 지도 화면에 보이는 남서쪽 및 북동쪽 좌표로 정의한 Bounding Box |
| Marker | 지도에서 위치가 있는 개별 거래 또는 장소 집계를 표시하는 점 |
| Cluster | 가까운 Marker 여러 개를 묶어 표시한 그룹 |
| 월별 비교 | 사용자 시간대를 기준으로 두 달의 지출 합계와 차이를 비교하는 기능 |
| 보관 처리 | 이미 사용된 카테고리를 삭제하지 않고 신규 선택 목록에서 숨기는 처리 |

## 5. 확정 전제와 제약

- Frontend는 Next.js, React, TypeScript 기반 모바일 우선 반응형 웹으로 구성한다.
- Backend는 Java 21, Spring Boot, Spring Data JPA 기반 모놀리식 애플리케이션으로 구성한다.
- Database는 PostgreSQL을 사용하고 스키마 변경은 Flyway Migration으로 관리한다.
- 로컬 개발 인프라는 Docker와 Docker Compose를 우선한다.
- 지도는 Kakao Maps JavaScript API, 현재 위치는 Web Geolocation API를 사용한다.
- 통신은 REST API와 JSON을 사용한다.
- 위치는 민감정보로 취급하며 거래 저장에 필수로 요구하지 않는다.
- MSA, Kubernetes, Redis, 메시지 큐, AI 기능, PostGIS는 검증된 필요가 없으면 도입하지 않는다.
- PostGIS 없이 위도, 경도와 Bounding Box 질의로 MVP 요구를 우선 충족한다.

## 6. 기능 요구사항

### 6.1 계정과 인증

#### FR-001 회원가입

- 설명: 사용자는 이메일과 비밀번호로 개인 계정을 생성할 수 있어야 한다.
- 사용자 가치: 자신의 거래와 위치 정보를 다른 사용자와 분리해 안전하게 관리할 수 있다.
- 입력: 이메일, 비밀번호, 비밀번호 확인, 필수 약관 동의 여부.
- 처리 규칙: 이메일은 앞뒤 공백 제거 후 대소문자를 구분하지 않는 고유값으로 검사한다. 비밀번호는 10자 이상 64자 이하이며 영문자와 숫자를 각각 1자 이상 포함한다. 비밀번호 원문은 저장하거나 로그에 남기지 않는다.
- 결과: 가입 성공 시 계정이 생성되고 로그인 가능한 상태가 된다.
- 예외 및 오류: 중복 이메일, 잘못된 이메일 형식, 비밀번호 정책 불충족, 약관 미동의, 서버 오류를 구분해 표시한다. 중복 여부를 제외한 내부 보안 정보는 노출하지 않는다.
- 우선순위: Must
- 완료 조건: 유효한 입력으로 계정이 1개 생성되고, 같은 이메일로 재가입할 수 없으며, 비밀번호 원문이 DB와 로그에 존재하지 않는다.

#### FR-002 로그인

- 설명: 등록된 사용자는 이메일과 비밀번호로 로그인할 수 있어야 한다.
- 사용자 가치: 본인 데이터에 안전하게 접근할 수 있다.
- 입력: 이메일, 비밀번호.
- 처리 규칙: 성공 시 인증 상태를 발급하고 보호된 요청에서 사용자 식별에 사용한다. 실패 응답은 이메일 존재 여부와 비밀번호 오류를 구분하지 않는다.
- 결과: 로그인 성공 후 기본 화면으로 이동한다.
- 예외 및 오류: 자격 증명 불일치, 비활성 계정, 요청 제한, 네트워크 및 서버 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 올바른 자격 증명으로 보호된 화면에 접근할 수 있고, 잘못된 자격 증명으로는 인증 상태가 생성되지 않는다.

#### FR-003 로그아웃과 인증 만료

- 설명: 사용자는 현재 인증 상태를 종료할 수 있어야 하며 만료된 인증은 자동으로 거부되어야 한다.
- 사용자 가치: 공용 기기나 분실 기기에서 계정 접근 위험을 줄일 수 있다.
- 입력: 로그아웃 요청 또는 만료된 인증 정보.
- 처리 규칙: 서버가 현재 세션을 무효화하고 인증 쿠키 만료 응답을 반환한 뒤 로그아웃 완료로 처리한다. 클라이언트는 개인 데이터 캐시를 비운다.
- 결과: 보호된 화면 접근 시 로그인 화면으로 이동한다.
- 예외 및 오류: 통신 실패 또는 응답 유실 시 개인 데이터 캐시를 비우고 logoutPending 상태에서 개인 화면과 자동 인증 갱신을 차단하며 재시도를 제공한다. 서버 응답으로 완료를 확인하기 전에는 성공으로 표시하지 않는다. 이 상태에서는 HttpOnly 쿠키 제거와 서버 세션 무효화를 보장하지 않는다.
- 우선순위: Must
- 완료 조건: 로그아웃 성공 응답 후 이전 인증 정보로 보호된 API를 호출할 수 없고 인증 쿠키가 만료된다. 통신 실패 시 개인 화면 및 자동 인증 갱신이 차단되고 성공 메시지 없이 재시도가 가능하다. 재시도 성공 후 로그아웃 완료 상태로 전환한다. 예외 규칙은 CHG-003으로 승인되었다.

#### FR-004 사용자 데이터 격리

- 설명: 모든 사용자 소유 데이터는 인증된 사용자 범위에서만 접근할 수 있어야 한다.
- 사용자 가치: 거래와 위치정보의 기밀성을 보장받는다.
- 입력: 거래, 카테고리, 장소, 통계 등의 조회 또는 변경 요청.
- 처리 규칙: 서버는 요청의 사용자 ID가 아니라 인증 주체를 기준으로 소유권을 판정한다. 다른 사용자 소유 ID를 전달해도 데이터 존재 여부를 과도하게 노출하지 않는다.
- 결과: 본인 데이터만 조회 및 변경된다.
- 예외 및 오류: 미인증은 401, 권한이 없는 접근은 정책에 따라 403 또는 404로 일관되게 처리한다.
- 우선순위: Must
- 완료 조건: 사용자 A의 인증으로 사용자 B의 거래, 위치, 카테고리, 통계를 읽거나 변경하거나 삭제할 수 없다.

### 6.2 거래와 카테고리

#### FR-005 거래 등록

- 설명: 사용자는 수입 또는 지출 거래를 등록할 수 있어야 한다.
- 사용자 가치: 일상 거래를 빠르고 정확하게 기록할 수 있다.
- 입력: 거래 유형, 금액, 카테고리, 거래일, 선택 메모, 선택 위치.
- 처리 규칙: 거래 유형, 금액, 카테고리, 거래일은 필수다. 메모와 위치는 선택이다. 금액과 날짜는 업무 규칙 BR-001부터 BR-005를 따른다.
- 결과: 거래가 저장되고 내역, 합계, 관련 지도와 통계에 반영된다.
- 예외 및 오류: 필수값 누락, 허용 범위 밖 금액, 잘못된 날짜, 사용할 수 없는 카테고리, 위치 형식 오류, 서버 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 위치 유무와 관계없이 유효한 거래가 한 번만 저장되고 해당 사용자의 조회 결과와 합계에 반영된다.

#### FR-006 거래 목록 조회

- 설명: 사용자는 자신의 거래를 최신 거래일 순으로 조회할 수 있어야 한다.
- 사용자 가치: 기록 내역을 검토하고 원하는 거래를 찾을 수 있다.
- 입력: 기간, 거래 유형, 카테고리, 위치 유무, 페이지 정보.
- 처리 규칙: 기본 기간은 현재 월이다. 거래일 내림차순, 기록 시각 내림차순으로 정렬한다. 페이지 크기는 기본 20개, 최대 100개다.
- 결과: 조건에 맞는 거래 목록, 페이지 정보, 기간 합계를 반환한다.
- 예외 및 오류: 잘못된 기간, 존재하지 않는 카테고리, 빈 결과, 네트워크 및 서버 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 필터와 정렬 규칙이 일관되고 사용자가 다음 페이지를 중복이나 누락 없이 조회할 수 있다.

#### FR-007 거래 상세 조회

- 설명: 사용자는 거래의 전체 입력값과 위치 상세를 조회할 수 있어야 한다.
- 사용자 가치: 저장된 내용을 확인하고 수정 여부를 판단할 수 있다.
- 입력: 거래 ID.
- 처리 규칙: 인증된 사용자의 소유권을 확인한다.
- 결과: 거래 유형, 금액, 카테고리, 거래일, 메모, 위치, 기록 및 수정 시각을 표시한다.
- 예외 및 오류: 존재하지 않거나 접근할 수 없는 거래는 일관된 찾을 수 없음 상태로 처리한다.
- 우선순위: Must
- 완료 조건: 본인 거래만 조회되고 저장된 선택값과 위치 출처가 정확히 표시된다.

#### FR-008 거래 수정

- 설명: 사용자는 본인의 거래 정보를 수정할 수 있어야 한다.
- 사용자 가치: 잘못 입력한 금액, 카테고리, 날짜, 메모, 위치를 바로잡을 수 있다.
- 입력: 거래 ID와 변경할 전체 거래 데이터.
- 처리 규칙: 등록과 동일한 검증을 적용한다. 위치를 제거하거나 다른 출처의 위치로 변경할 수 있다. 수정 시각을 갱신한다.
- 결과: 수정된 거래가 내역, 지도, 통계에 반영된다.
- 예외 및 오류: 소유권 오류, 동시 수정 충돌, 유효하지 않은 값, 서버 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 수정 성공 후 이전 값이 합계와 통계에서 제거되고 새 값이 한 번만 반영된다.

#### FR-009 거래 삭제

- 설명: 사용자는 본인의 거래를 확인 후 삭제할 수 있어야 한다.
- 사용자 가치: 중복 또는 잘못된 기록을 제거할 수 있다.
- 입력: 거래 ID와 삭제 확인.
- 처리 규칙: 삭제 전 거래의 핵심 정보를 포함한 확인 절차를 제공한다. 삭제 정책은 BR-013을 따른다.
- 결과: 삭제된 거래는 내역, 지도, 통계에서 제외된다.
- 예외 및 오류: 소유권 오류, 이미 삭제된 거래, 네트워크 및 서버 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 삭제 성공 후 일반 조회와 모든 집계 결과에서 해당 거래가 제외되고 반복 삭제 요청이 데이터 손상을 일으키지 않는다.

#### FR-010 카테고리 조회와 선택

- 설명: 사용자는 거래 유형에 맞는 활성 카테고리를 조회하고 선택할 수 있어야 한다.
- 사용자 가치: 일관된 분류로 거래를 빠르게 입력하고 통계를 확인할 수 있다.
- 입력: 거래 유형.
- 처리 규칙: 지출과 수입 카테고리를 구분한다. 기본 카테고리와 사용자 정의 카테고리를 함께 제공하며 보관된 카테고리는 신규 거래 선택 목록에서 제외한다.
- 결과: 정렬된 활성 카테고리 목록을 반환한다.
- 예외 및 오류: 목록 로딩 실패 시 재시도와 오류 상태를 표시한다.
- 우선순위: Must
- 완료 조건: 거래 유형이 다른 카테고리를 선택할 수 없고 활성 카테고리만 신규 입력에 표시된다.

#### FR-011 사용자 정의 카테고리 관리

- 설명: 사용자는 개인 카테고리를 생성, 이름 변경, 보관할 수 있어야 한다.
- 사용자 가치: 자신의 소비 분류 방식에 맞게 기록할 수 있다.
- 입력: 거래 유형, 카테고리명, 선택 색상 또는 아이콘.
- 처리 규칙: 동일 사용자와 거래 유형 안에서 앞뒤 공백을 제거한 이름은 대소문자를 구분하지 않고 중복될 수 없다. 사용 중인 카테고리는 삭제 대신 보관한다.
- 결과: 카테고리 선택 목록과 기존 거래 표시에 일관되게 반영된다.
- 예외 및 오류: 빈 이름, 중복 이름, 길이 초과, 기본 카테고리 변경 제한을 처리한다.
- 우선순위: Should
- 완료 조건: 새 카테고리로 거래를 등록할 수 있고 보관 후 기존 거래의 카테고리명은 유지되며 신규 선택 목록에서는 제외된다.

### 6.3 선택적 위치 입력과 장소

#### FR-012 위치 없이 거래 저장

- 설명: 사용자는 위치 권한이나 지도 기능 없이 거래를 저장할 수 있어야 한다.
- 사용자 가치: 위치 공유를 원하지 않거나 빠른 기록이 필요할 때 핵심 기능을 계속 사용할 수 있다.
- 입력: 위치 출처 "없음" 또는 위치 입력 건너뛰기.
- 처리 규칙: 위치 관련 필드는 모두 비워 저장하고 위치 미입력을 오류로 취급하지 않는다.
- 결과: 거래는 일반 내역과 비위치 기반 합계에 반영되지만 지도 및 장소, 지역 통계에서는 제외된다.
- 예외 및 오류: 지도 로딩 실패 중에도 위치 없이 계속하기 동작을 제공한다.
- 우선순위: Must
- 완료 조건: 위치 권한을 거부하거나 지도 키가 없어도 유효한 거래를 등록, 조회, 수정, 삭제할 수 있다.

#### FR-013 현재 위치 사용

- 설명: 사용자는 명시적으로 요청해 브라우저의 현재 위치를 거래에 연결할 수 있어야 한다.
- 사용자 가치: 장소 검색 없이 현재 소비 위치를 빠르게 기록할 수 있다.
- 입력: 현재 위치 사용 동작, 브라우저 위치 권한 결과.
- 처리 규칙: 사용자 동작 전에는 위치 권한을 요청하지 않는다. 획득한 위도, 경도, 정확도, 획득 시각을 검증한다. 주소 변환이 실패해도 좌표 사용 여부를 사용자가 확인할 수 있다.
- 결과: 지도 미리보기와 사용 가능한 주소를 표시하고 확인 시 거래 위치로 저장한다.
- 예외 및 오류: 권한 거부, 지원하지 않는 브라우저, 시간 초과, 위치 불가, 정확도 부족, 네트워크 실패를 구분하고 위치 없이 계속하기를 제공한다.
- 우선순위: Must
- 완료 조건: 권한 허용 시 좌표가 미리보기와 저장 결과에 반영되고, 권한 거부 시 거래 입력값을 잃지 않은 채 다른 위치 방식 또는 위치 없음을 선택할 수 있다.

#### FR-014 장소 검색

- 설명: 사용자는 키워드로 장소를 검색해 거래 위치를 선택할 수 있어야 한다.
- 사용자 가치: 현재 위치와 다른 장소나 과거 거래의 장소를 정확히 기록할 수 있다.
- 입력: 2자 이상의 검색어, 선택 지도 중심 또는 현재 위치.
- 처리 규칙: 검색어 입력은 300ms 이상 지연 후 요청하고 이전 요청을 취소하거나 최신 응답만 반영한다. 결과에는 장소명, 주소, 거리 또는 지역 정보를 표시한다.
- 결과: 선택한 장소의 외부 장소 ID, 장소명, 주소, 좌표, 위치 출처를 거래 입력에 반영한다.
- 예외 및 오류: 검색 결과 없음, 지도 키 미설정, 호출 한도 초과, 네트워크 및 SDK 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 검색 결과 하나를 선택해 거래를 저장하면 동일한 장소명과 좌표가 상세, 지도, 장소 통계에 표시된다.

#### FR-015 지도 직접 선택

- 설명: 사용자는 지도에서 한 지점을 직접 선택하거나 선택 지점을 이동할 수 있어야 한다.
- 사용자 가치: 검색되지 않는 장소나 정확한 지점을 기록할 수 있다.
- 입력: 지도 탭 또는 클릭, 지도 이동, 선택 확정.
- 처리 규칙: 선택 지점에 Marker를 표시하고 좌표와 가능한 주소 스냅샷을 보여준다. 주소 변환 실패는 좌표 선택을 막지 않는다.
- 결과: 좌표, 선택 주소, 위치 출처를 거래 입력에 반영한다.
- 예외 및 오류: 지도 로딩 실패, 주소 변환 실패, 네트워크 오류 시 재시도와 위치 없이 계속하기를 제공한다.
- 우선순위: Must
- 완료 조건: 사용자가 확정한 지점과 저장된 좌표의 차이가 표시 정밀도 범위 안에서 일치한다.

#### FR-016 위치 확인과 변경

- 설명: 거래 저장 전 선택한 위치를 확인, 변경, 제거할 수 있어야 한다.
- 사용자 가치: 잘못된 장소나 의도하지 않은 위치 저장을 방지할 수 있다.
- 입력: 위치 변경 또는 제거 동작.
- 처리 규칙: 위치 출처, 장소명 또는 주소, 지도 미리보기를 표시한다. 위치 제거 시 관련 필드를 모두 제거한다.
- 결과: 최종 확인한 위치만 거래에 연결된다.
- 예외 및 오류: 지도 미리보기가 실패해도 텍스트와 좌표 확인 및 위치 제거가 가능해야 한다.
- 우선순위: Must
- 완료 조건: 저장 전에 위치를 제거하면 서버에 장소명, 주소, 좌표, 외부 장소 ID가 저장되지 않는다.

#### FR-017 장소 식별과 중복 처리

- 설명: 시스템은 같은 검색 장소를 일관되게 식별하고 수동 좌표의 과도한 자동 병합을 방지해야 한다.
- 사용자 가치: 장소별 합계가 중복되거나 서로 다른 장소가 잘못 합쳐지는 문제를 줄인다.
- 입력: 외부 장소 ID, 정규화한 장소명, 좌표, 위치 출처.
- 처리 규칙: Kakao 검색 결과는 Kakao 장소 ID를 우선 동일 장소 기준으로 사용한다. 현재 위치나 지도 직접 선택은 자동으로 기존 장소와 병합하지 않고 거래 위치 스냅샷으로 저장한다. 사용자가 명시적으로 같은 장소를 선택하는 기능은 후속 범위로 둔다.
- 결과: 검색으로 선택한 같은 장소는 장소별 통계에서 하나로 집계되고, 불확실한 좌표는 별도 항목으로 유지된다.
- 예외 및 오류: 외부 장소 ID가 없거나 변경되면 좌표와 이름을 표시하되 자동 병합하지 않는다.
- 우선순위: Must
- 완료 조건: 동일 Kakao 장소 ID의 지출은 한 장소로 집계되고 서로 다른 장소 ID는 이름이 같아도 자동 병합되지 않는다.

### 6.4 지도 조회

#### FR-018 지도 소비 조회

- 설명: 사용자는 위치가 저장된 지출을 지도에서 조회할 수 있어야 한다.
- 사용자 가치: 소비가 발생한 장소와 분포를 직관적으로 파악할 수 있다.
- 입력: 기간, 지출 카테고리, 지도 영역, Zoom Level.
- 처리 규칙: 기본 기간은 현재 월이며 지출만 포함한다. 서버는 현재 Bounding Box 안의 데이터만 반환한다. 수입과 위치 없는 지출은 기본 지도 결과에서 제외한다.
- 결과: 조건에 맞는 Marker 또는 Cluster와 기간 합계, 위치 포함 건수를 표시한다.
- 예외 및 오류: 데이터 없음, 지도 키 미설정, 네트워크 오류, 잘못된 영역, 요청 취소를 구분한다.
- 우선순위: Must
- 완료 조건: 필터와 지도 영역을 변경하면 화면 밖 데이터가 제외되고 조건에 맞는 위치 지출만 표시된다.

#### FR-019 Marker와 Cluster 표시

- 설명: 지도는 데이터 밀도와 Zoom Level에 따라 개별 Marker와 Cluster를 적절히 표시해야 한다.
- 사용자 가치: 많은 거래가 있어도 지도를 읽고 탐색할 수 있다.
- 입력: 위치 거래 또는 장소 집계, Zoom Level.
- 처리 규칙: 같은 검색 장소의 복수 거래는 하나의 장소 Marker와 합계로 표현한다. 가까운 Marker는 클라이언트 Cluster로 묶는다. Cluster 선택 시 확대하거나 포함 범위를 표시한다.
- 결과: Marker에는 금액 또는 건수의 핵심 정보가, Cluster에는 포함 건수가 표시된다.
- 예외 및 오류: 일부 Marker 렌더링 실패가 전체 지도 조작을 막지 않아야 한다.
- 우선순위: Must
- 완료 조건: 동일 장소의 거래가 겹쳐 보이지 않고, 500개 위치 결과에서도 지도 이동과 확대가 가능하며 Cluster 선택이 동작한다.

#### FR-020 지도 상세 정보

- 설명: 사용자는 Marker를 선택해 해당 장소 또는 위치의 소비 상세를 확인할 수 있어야 한다.
- 사용자 가치: 지도에서 금액의 근거 거래를 바로 확인할 수 있다.
- 입력: Marker 선택.
- 처리 규칙: 모바일에서는 Bottom Sheet를 기본으로 사용한다. 장소명 또는 주소, 기간 합계, 거래 건수, 최근 거래 목록을 표시한다.
- 결과: 상세에서 거래 상세 화면으로 이동할 수 있다.
- 예외 및 오류: 장소명이 없으면 주소 또는 좌표 기반 대체명을 표시한다. 상세 로딩 실패 시 지도 상태를 유지한다.
- 우선순위: Must
- 완료 조건: Marker 합계와 Bottom Sheet의 거래 합계가 같고 각 거래 상세로 이동할 수 있다.

#### FR-021 지도 필터와 상태 유지

- 설명: 사용자는 기간과 카테고리를 변경하고 지도 이동 후 결과를 갱신할 수 있어야 한다.
- 사용자 가치: 원하는 소비 범위를 반복 탐색할 수 있다.
- 입력: 시작일, 종료일, 다중 카테고리, 지도 영역, Zoom Level.
- 처리 규칙: 지도 이동 중 연속 요청을 제한하고 마지막 영역만 조회한다. 상세 화면에서 돌아오면 직전 필터와 지도 중심을 유지한다.
- 결과: 활성 필터를 눈에 보이게 표시하고 초기화 기능을 제공한다.
- 예외 및 오류: 잘못된 기간은 요청 전에 차단하고 재조회 실패 시 직전 지도 결과와 오류 표시를 함께 유지한다.
- 우선순위: Should
- 완료 조건: 필터 적용, 초기화, 상세 왕복 후 상태 복원이 정의된 규칙대로 동작한다.

### 6.5 통계

#### FR-022 기간 요약 통계

- 설명: 사용자는 선택 기간의 수입, 지출, 잔액, 거래 건수를 확인할 수 있어야 한다.
- 사용자 가치: 재정 흐름을 한눈에 파악할 수 있다.
- 입력: 시작일, 종료일.
- 처리 규칙: BR-001의 합계 규칙을 사용하며 위치 유무와 관계없이 모든 거래를 포함한다.
- 결과: 수입 합계, 지출 합계, 잔액, 수입 및 지출 건수를 표시한다.
- 예외 및 오류: 거래 없음은 0으로 표시하고 서버 오류와 구분한다.
- 우선순위: Must
- 완료 조건: 같은 기간 거래 목록의 합계와 요약 통계가 정확히 일치한다.

#### FR-023 카테고리별 지출 통계

- 설명: 사용자는 기간별 지출을 카테고리별로 비교할 수 있어야 한다.
- 사용자 가치: 어떤 목적에 가장 많이 소비했는지 알 수 있다.
- 입력: 기간, 선택 위치 또는 지역 필터.
- 처리 규칙: 지출만 포함하고 합계 내림차순으로 정렬한다. 전체 대비 비율은 소수점 첫째 자리에서 반올림해 정수 퍼센트로 표시하되 원금 합계는 정수로 유지한다.
- 결과: 카테고리명, 금액, 비율, 건수를 표시한다.
- 예외 및 오류: 지출 합계가 0이면 모든 비율은 0으로 표시한다.
- 우선순위: Must
- 완료 조건: 카테고리별 금액 합계가 같은 조건의 전체 지출 합계와 일치한다.

#### FR-024 장소별 지출 통계

- 설명: 사용자는 검색으로 식별된 장소별 지출 합계와 거래를 확인할 수 있어야 한다.
- 사용자 가치: 특정 매장이나 장소에서 누적 소비한 금액을 알 수 있다.
- 입력: 기간, 카테고리, 정렬, 페이지 정보.
- 처리 규칙: FR-017의 장소 식별 규칙을 사용한다. 장소로 식별되지 않은 좌표는 별도 "직접 선택 위치" 그룹으로 표시하거나 장소별 순위에서 제외하고 별도 건수로 알린다.
- 결과: 장소명, 주소, 합계, 건수, 최근 거래일과 상세 이동을 제공한다.
- 예외 및 오류: 장소 데이터 없음, 외부 장소 정보 변경, 네트워크 오류를 처리한다.
- 우선순위: Must
- 완료 조건: 동일 장소 ID의 거래 합계가 정확하고 장소 상세의 거래 목록과 일치한다.

#### FR-025 지역별 지출 통계

- 설명: 사용자는 행정구역 단위로 지출 분포를 확인할 수 있어야 한다.
- 사용자 가치: 어느 지역에서 가장 많이 소비했는지 비교할 수 있다.
- 입력: 기간, 카테고리, 지역 집계 수준.
- 처리 규칙: 저장된 주소 스냅샷의 지역 코드 또는 지역명을 사용하며, 주소가 없는 좌표는 "지역 미분류"로 집계한다. 확정 기본 집계 단위는 시군구다.
- 결과: 지역명, 합계, 건수, 비율을 합계 내림차순으로 표시한다.
- 예외 및 오류: 행정구역 경계 또는 주소 변환 실패는 지역 미분류로 처리하고 전체 위치 지출 건수와 차이를 표시한다.
- 우선순위: Must
- 완료 조건: 각 거래가 하나의 지역 또는 지역 미분류에만 포함되고 지역 합계가 위치 있는 지출 합계와 일치한다.

#### FR-026 월별 비교

- 설명: 사용자는 선택 월과 직전 월의 지출을 비교할 수 있어야 한다.
- 사용자 가치: 소비 규모와 소비 지역의 변화를 파악할 수 있다.
- 입력: 기준 연월, 선택 카테고리.
- 처리 규칙: 사용자 시간대의 월 시작일부터 말일까지를 사용한다. 전체 지출, 카테고리별, 상위 지역별 금액 차이와 증감률을 계산한다. 이전 값이 0이면 증감률 대신 "비교 불가"를 표시한다.
- 결과: 두 달의 합계, 금액 차이, 증감률 또는 비교 불가, 상위 변화 항목을 표시한다.
- 예외 및 오류: 한쪽 달 데이터가 없으면 0으로 표시하되 데이터 없음 상태를 함께 알린다.
- 우선순위: Should
- 완료 조건: 월 경계와 합계가 BR-005의 시간대 규칙을 따르고 0으로 나누는 계산이 발생하지 않는다.

### 6.6 계정 데이터 관리

#### FR-027 계정 설정 조회와 변경

- 설명: 사용자는 자신의 표시 이름, 시간대 등 지원되는 설정을 조회하고 변경할 수 있어야 한다.
- 사용자 가치: 날짜와 통계 기준을 자신의 환경에 맞출 수 있다.
- 입력: 표시 이름, 시간대.
- 처리 규칙: 시간대는 IANA 식별자만 허용한다. 시간대 변경은 이후 조회의 날짜 경계에 적용하고 기존 거래일 자체는 변경하지 않는다.
- 결과: 변경된 설정이 화면과 집계 기준에 반영된다.
- 예외 및 오류: 지원하지 않는 시간대, 잘못된 이름, 서버 오류를 처리한다.
- 우선순위: Could
- 완료 조건: 설정 변경 후 재로그인해도 값이 유지되고 기간 집계가 선택 시간대를 사용한다.

#### FR-028 계정 탈퇴

- 설명: 사용자는 본인 확인 후 계정과 관련 데이터를 삭제하도록 요청할 수 있어야 한다.
- 사용자 가치: 서비스 이용 종료 시 개인정보와 위치정보를 통제할 수 있다.
- 입력: 현재 비밀번호 또는 동등한 재인증, 삭제 확인 문구.
- 처리 규칙: 영향과 취소 불가 여부를 명확히 알리고 재인증 후 처리한다. 상세 삭제 정책은 BR-014를 따른다.
- 결과: 활성 계정과 인증 상태가 종료되고 사용자 데이터가 삭제 절차에 들어간다.
- 예외 및 오류: 재인증 실패, 처리 중 오류, 이미 탈퇴한 계정을 처리한다.
- 우선순위: Must
- 완료 조건: 탈퇴 완료 후 로그인할 수 없고 활성 DB에서 해당 사용자의 거래, 위치, 카테고리를 조회할 수 없다.

## 7. 비기능 요구사항

### NFR-001 모바일 반응형

- 측정 기준: 360px부터 1440px 너비에서 가로 스크롤 없이 핵심 기능을 사용할 수 있어야 한다. 주요 터치 대상은 최소 44px x 44px를 확보한다.
- 검증 방법: Android Chrome, iOS Safari 및 데스크톱 반응형 뷰에서 화면별 수동 및 E2E 테스트를 수행한다.

### NFR-002 접근성

- 측정 기준: 핵심 흐름은 WCAG 2.2 AA 수준을 목표로 하며 키보드만으로 수행할 수 있어야 한다. 입력 요소는 연결된 레이블, 오류 설명, 가시적 포커스를 가져야 한다. 색상만으로 상태를 구분하지 않는다.
- 검증 방법: 자동 접근성 검사와 키보드 탐색, 스크린 리더 기본 흐름 수동 테스트를 수행한다.

### NFR-003 API 응답시간

- 측정 기준: 개발 기준 데이터인 사용자당 거래 10,000건에서 일반 조회 및 변경 API의 p95는 서버 처리시간 500ms 이하, 지도 영역 조회와 통계 API의 p95는 1,000ms 이하여야 한다.
- 검증 방법: 고정 Seed 데이터와 부하 테스트 스크립트로 동일 조건을 반복 측정한다.

### NFR-004 초기 로딩과 지도 렌더링

- 측정 기준: 중급 모바일 기기와 Fast 4G 조건에서 인증 후 핵심 화면의 Largest Contentful Paint는 2.5초 이하를 목표로 한다. 지도 화면은 SDK 로드 후 3초 안에 조작 가능한 상태가 되고 500개 위치 결과의 Marker 또는 Cluster 표시를 2초 안에 완료해야 한다.
- 검증 방법: 브라우저 성능 측정과 E2E 타이밍 로그로 확인한다.

### NFR-005 인증과 인가 보안

- 측정 기준: 모든 보호 API는 인증을 요구하며 객체 단위 소유권 검사를 수행한다. 비밀번호는 검증된 단방향 해시로 저장하고 인증 쿠키를 사용할 경우 HttpOnly, Secure, SameSite 속성을 적용한다.
- 검증 방법: 미인증, 다른 사용자 ID, 변조 인증 정보, 만료 인증 정보를 사용한 통합 및 보안 테스트를 수행한다.

### NFR-006 입력 검증과 애플리케이션 보안

- 측정 기준: 서버는 모든 입력을 독립적으로 검증한다. CORS는 허용된 Frontend Origin으로 제한하고 선택한 인증 방식에 맞는 CSRF 방어를 적용한다. 오류 응답에 스택 트레이스나 내부 SQL을 노출하지 않는다.
- 검증 방법: 경계값, 변조 요청, 허용되지 않은 Origin, XSS 문자열, SQL 삽입 패턴을 사용한 테스트를 수행한다.

### NFR-007 Secret과 로그

- 측정 기준: 비밀번호, API Key, JWT Secret, DB Password, OAuth Secret, Token을 소스, 응답, 일반 로그에 기록하지 않는다. 위도와 경도, 전체 주소, 이메일은 기본 정보 로그에 기록하지 않는다.
- 검증 방법: 저장소 Secret 검사와 정상 및 오류 시나리오 로그 검토를 수행한다.

### NFR-008 위치정보 최소 수집

- 측정 기준: 위치는 거래 입력 중 사용자가 명시적으로 선택한 경우에만 요청하고 저장한다. 백그라운드 추적, 위치 이력 수집, 불필요한 원본 Geolocation 응답 저장을 금지한다.
- 검증 방법: 권한 요청 시점, 네트워크 요청, DB 저장 필드를 각 위치 흐름별로 확인한다.

### NFR-009 개인정보 삭제

- 측정 기준: 거래 삭제 시 일반 조회에서 즉시 제거하고, 계정 탈퇴 시 활성 데이터에서 사용자 식별 정보와 위치정보를 즉시 접근 불가하게 한다. 백업 보존 기간은 최대 30일로 하며 정책 문서에 명시한다.
- 검증 방법: 삭제 및 탈퇴 후 API, DB, 인증 상태를 확인하고 백업 정책을 문서 검토한다.

### NFR-010 신뢰성과 오류 복구

- 측정 기준: 변경 요청은 성공 또는 실패가 명확해야 하며 재시도로 중복 거래가 생기지 않아야 한다. 지도, 검색, 위치 기능 실패가 거래 입력값을 지우거나 위치 없는 저장을 막지 않아야 한다.
- 검증 방법: 네트워크 중단, 요청 시간 초과, 중복 제출, 외부 SDK 오류를 주입한 통합 및 E2E 테스트를 수행한다.

### NFR-011 브라우저 호환성과 HTTPS

- 측정 기준: 출시 시점 기준 최신 2개 주요 버전의 Android Chrome, iOS Safari, 데스크톱 Chrome, Edge, Safari를 지원한다. 운영 환경은 HTTPS를 사용한다.
- 검증 방법: 브라우저별 핵심 흐름 테스트와 HTTPS 환경의 Geolocation 테스트를 수행한다.

### NFR-012 유지보수성과 테스트 가능성

- 측정 기준: Controller에 비즈니스 로직을 두지 않고 DTO, Validation, 전역 예외 처리, 명확한 Transaction 범위를 사용한다. Entity를 API 응답으로 직접 반환하지 않는다. Frontend는 명시적 타입을 사용하고 any를 원칙적으로 금지한다.
- 검증 방법: 정적 분석, 코드 리뷰, 단위 및 통합 테스트와 아키텍처 규칙 검사를 수행한다.

### NFR-013 관측성

- 측정 기준: 요청 추적 ID, HTTP 상태, 경로 템플릿, 처리시간을 구조화 로그로 기록한다. 개인정보와 Secret은 제외한다. 외부 지도 및 검색 오류는 사용자 오류와 구분 가능한 코드로 집계한다.
- 검증 방법: 정상, 검증 실패, 인증 실패, 외부 연동 실패 로그를 점검한다.

### NFR-014 금액 정밀도

- 측정 기준: 금액은 부동소수점으로 저장하거나 계산하지 않는다. KRW 기본안에서는 1원 단위 정수로 저장하고 합계에서도 정밀도 손실이 없어야 한다.
- 검증 방법: 최소값, 최대값, 다건 합계, 수정 및 삭제 후 재집계 테스트를 수행한다.

### NFR-015 날짜와 시간대

- 측정 기준: 거래일은 시간 없는 달력 날짜로 저장하고 기록 및 수정 시각은 UTC instant로 저장한다. 기간과 월 경계는 사용자 시간대 기준으로 계산한다.
- 검증 방법: 월말, 연말, 윤년, UTC 날짜 전환 전후와 서로 다른 시간대 테스트를 수행한다.

## 8. 업무 규칙

### BR-001 거래 유형과 합계

- 거래 금액은 항상 0보다 큰 절대값으로 저장한다.
- 거래 유형은 INCOME 또는 EXPENSE로 구분한다.
- 수입 합계는 INCOME 금액의 합, 지출 합계는 EXPENSE 금액의 합이다.
- 잔액은 수입 합계에서 지출 합계를 뺀 값이다.
- 지도와 소비 통계의 기본 대상은 EXPENSE다.

### BR-002 금액 범위와 통화

- 기본 통화는 KRW 단일 통화다.
- KRW 금액은 소수점을 허용하지 않는다.
- 한 거래의 허용 범위는 1원 이상 999,999,999,999원 이하다.
- 다른 통화와 환율 변환은 MVP에 포함하지 않는다.

### BR-003 거래일

- 거래일은 사용자가 입력한 실제 거래 날짜다.
- 기본값은 사용자 시간대의 오늘이다.
- 미래 날짜는 기본적으로 허용하지 않는다. 당일 이후 거래는 검증 오류로 처리한다.
- 기록 시각과 수정 시각은 서버에서 생성하며 사용자가 수정할 수 없다.

### BR-004 메모

- 메모는 선택값이며 앞뒤 공백을 제거한다.
- 빈 문자열은 미입력으로 저장한다.
- 최대 길이는 500자다.

### BR-005 날짜와 시간대

- 사용자 시간대의 기본값은 Asia/Seoul이다.
- 거래일은 DATE로, 생성 및 수정 시각은 UTC 기준 시각으로 저장한다.
- 일, 월, 기간 집계 경계는 사용자 시간대를 기준으로 계산한다.

### BR-006 기본 카테고리

- 지출 기본 카테고리 권장안: 식비, 카페, 교통, 쇼핑, 주거, 생활, 의료, 문화, 여행, 교육, 기타.
- 수입 기본 카테고리 권장안: 급여, 용돈, 사업, 금융, 기타.
- 기본 카테고리의 최종 명칭과 아이콘은 화면 설계 전에 확정한다.

### BR-007 사용자 정의 카테고리

- 카테고리명은 1자 이상 30자 이하다.
- 같은 사용자와 거래 유형 안에서 정규화한 이름은 중복될 수 없다.
- 사용된 카테고리는 하드 삭제하지 않고 보관한다.
- 보관된 카테고리는 기존 거래와 통계에 원래 이름으로 표시한다.

### BR-008 위치 선택성

- 모든 거래는 위치 없이 저장할 수 있다.
- 사용자가 현재 위치, 장소 검색, 지도 직접 선택 중 하나를 명시적으로 완료했을 때만 위치를 저장한다.
- 지출 등록 화면을 열었다는 이유만으로 위치 권한을 요청하지 않는다.
- 수입에도 위치를 연결할 수 있으나 지도와 소비 통계의 기본 대상에서는 제외한다.

### BR-009 좌표와 정확도

- 위도 범위는 -90 이상 90 이하, 경도 범위는 -180 이상 180 이하다.
- 좌표는 최소 소수점 6자리 정밀도를 보존할 수 있는 정확한 숫자 타입을 사용한다.
- 현재 위치의 오차 반경 accuracyM이 1,000m를 초과하면 경고하고 사용자가 재시도, 그대로 사용, 위치 없이 계속하기 중 하나를 선택하게 한다. 1,000m 이하는 경고 대상이 아니다.
- 정확도 값은 현재 위치 출처에서만 저장하고 검색 또는 지도 선택에는 적용하지 않는다.

### BR-010 주소 스냅샷

- 장소명과 주소는 거래 저장 시점의 표시용 스냅샷으로 저장한다.
- 외부 서비스의 장소명이 나중에 바뀌어도 과거 거래의 표시값을 자동 변경하지 않는다.
- 도로명 주소를 우선하고 없으면 지번 주소를 저장한다.
- 주소 변환에 실패해도 유효한 좌표는 저장할 수 있다.

### BR-011 동일 장소 판정

- 검색 장소는 외부 제공자와 외부 장소 ID 조합으로 동일성을 판정한다.
- 이름만 같거나 가까운 좌표라는 이유로 자동 병합하지 않는다.
- 현재 위치와 지도 직접 선택 좌표는 MVP에서 별도 위치 스냅샷으로 취급한다.

### BR-012 지역 집계

- 기본 집계 단위는 대한민국 시군구다.
- 저장된 행정구역 코드가 있으면 코드를 우선하고, 없으면 저장된 지역명 스냅샷을 사용한다.
- 주소가 없거나 판정할 수 없는 위치는 "지역 미분류"로 한 번만 집계한다.
- 행정구역 경계선의 좌표는 외부 주소 변환 결과 하나를 사용하며 임의로 복수 지역에 배분하지 않는다.

### BR-013 거래 삭제

- MVP에서 거래 삭제는 확인 후 하드 삭제한다.
- 삭제 직후 내역, 지도, 통계에서 제거한다.
- 삭제 복구함과 변경 이력은 후속 범위다.

### BR-014 계정 탈퇴와 데이터 보존

- 탈퇴는 재인증과 명시적 최종 확인 후 수행한다.
- 활성 DB의 사용자, 거래, 위치, 사용자 카테고리 데이터는 하나의 일관된 절차로 삭제한다.
- 운영 백업에 남은 데이터는 최대 보존 기간 30일이 지나면 삭제되며 그동안 일반 서비스에서 복원하거나 조회하지 않는다.

### BR-015 월별 비교

- 기준 월과 직전 달을 같은 사용자 시간대로 비교한다.
- 금액 차이는 기준 월 금액에서 직전 월 금액을 뺀 값이다.
- 증감률은 `(기준 월 - 직전 월) / 직전 월 * 100`이다.
- 직전 월 금액이 0이면 증감률을 계산하지 않고 "비교 불가"로 표시한다.

## 9. Use Case와 예외 흐름

### UC-001 첫 방문과 회원가입 로그인

- 선행 조건: 사용자는 인증되지 않았다.
- 성공 흐름: 시작 화면 진입 -> 회원가입 선택 -> 이메일과 비밀번호 입력 -> 유효성 확인 -> 계정 생성 -> 로그인 -> 기본 화면 진입.
- 실패 흐름: 중복 이메일이나 입력 오류를 해당 필드에 표시하고 입력값을 유지한다. 서버 오류 시 재시도를 제공한다.
- 대체 흐름: 기존 사용자는 로그인 화면으로 이동해 로그인한다.
- 관련 요구사항: FR-001, FR-002, FR-003, FR-004.

### UC-002 위치 없이 빠른 지출 등록

- 선행 조건: 사용자가 로그인했다.
- 성공 흐름: 등록 진입 -> 지출 선택 -> 금액, 카테고리, 날짜 입력 -> 위치 입력 건너뛰기 -> 저장 -> 완료 표시.
- 실패 흐름: 필수값 또는 금액 오류를 표시하고 입력값을 유지한다. 중복 제출은 한 건만 저장한다.
- 대체 흐름: 저장 전에 메모를 추가하거나 위치 입력으로 전환한다.
- 관련 요구사항: FR-005, FR-010, FR-012.

### UC-003 현재 위치로 지출 등록

- 선행 조건: 사용자가 로그인했고 HTTPS 환경에서 위치 기능을 사용할 수 있다.
- 성공 흐름: 거래 입력 -> 현재 위치 선택 -> 권한 허용 -> 좌표 획득 -> 미리보기 확인 -> 저장.
- 실패 흐름: 권한 거부, 시간 초과, 낮은 정확도, 주소 변환 실패를 안내한다.
- 대체 흐름: 재시도, 장소 검색, 지도 선택 또는 위치 없이 저장한다.
- 관련 요구사항: FR-005, FR-013, FR-016.

### UC-004 장소 검색으로 지출 등록

- 선행 조건: 사용자가 로그인했고 Kakao Maps 검색 기능을 사용할 수 있다.
- 성공 흐름: 거래 입력 -> 장소 검색 -> 결과 선택 -> 지도와 주소 확인 -> 저장.
- 실패 흐름: 결과 없음, 호출 한도, 네트워크 또는 SDK 오류를 안내하고 입력값을 유지한다.
- 대체 흐름: 검색어 변경, 지도 선택, 현재 위치 또는 위치 없이 저장한다.
- 관련 요구사항: FR-005, FR-014, FR-016, FR-017.

### UC-005 지도 직접 선택으로 지출 등록

- 선행 조건: 사용자가 로그인했고 지도를 불러올 수 있다.
- 성공 흐름: 거래 입력 -> 지도 선택 -> 지도 이동 -> 지점 선택 -> 주소 또는 좌표 확인 -> 저장.
- 실패 흐름: 지도나 주소 변환 실패를 안내한다.
- 대체 흐름: 지도 재시도, 장소 검색 또는 위치 없이 저장한다.
- 관련 요구사항: FR-005, FR-015, FR-016.

### UC-006 거래 수정과 삭제

- 선행 조건: 본인 거래가 존재한다.
- 성공 흐름: 내역 조회 -> 거래 선택 -> 수정 또는 삭제 -> 검증 또는 확인 -> 결과 반영.
- 실패 흐름: 다른 기기에서 변경된 경우 최신 상태를 다시 불러오도록 안내한다. 네트워크 실패 시 결과를 성공으로 표시하지 않는다.
- 대체 흐름: 취소하면 변경 없이 상세로 돌아간다.
- 관련 요구사항: FR-006, FR-007, FR-008, FR-009.

### UC-007 지도에서 소비 탐색

- 선행 조건: 사용자가 로그인했고 위치가 저장된 지출이 있다.
- 성공 흐름: 지도 진입 -> 현재 월 결과 표시 -> 기간 또는 카테고리 변경 -> 지도 이동 및 확대 -> Marker 선택 -> Bottom Sheet 확인 -> 거래 상세 이동.
- 실패 흐름: 데이터 없음, 지도 키 미설정, 네트워크 실패를 구분해 표시한다.
- 대체 흐름: 필터 초기화, 재시도 또는 거래 내역으로 이동한다.
- 관련 요구사항: FR-018, FR-019, FR-020, FR-021.

### UC-008 장소 지역 기간 통계 확인

- 선행 조건: 사용자가 로그인했고 조회 가능한 거래가 있다.
- 성공 흐름: 통계 진입 -> 기간 선택 -> 요약 확인 -> 카테고리, 장소, 지역 탭 탐색 -> 항목 상세 확인.
- 실패 흐름: 데이터 없음은 0과 빈 상태로 표시하고 통신 오류와 구분한다.
- 대체 흐름: 기간 또는 카테고리를 변경한다.
- 관련 요구사항: FR-022, FR-023, FR-024, FR-025, FR-026.

### UC-009 위치 권한 거부 또는 지도 연동 실패

- 선행 조건: 사용자가 거래를 입력 중이다.
- 성공 흐름: 실패 원인 안내 -> 위치 없이 계속하기 선택 -> 기존 거래 입력 유지 -> 저장.
- 실패 흐름: 거래 저장 자체가 실패하면 위치 오류와 구분해 표시하고 재시도를 제공한다.
- 대체 흐름: 현재 위치 대신 장소 검색 또는 지도 선택을 사용한다. 지도 전체가 실패하면 위치 없이 저장한다.
- 관련 요구사항: FR-012, FR-013, FR-014, FR-015, NFR-010.

| 거래 등록 | 하단 등록 | 거래 입력 | 유형, 금액, 카테고리, 날짜, 메모, 위치 | 저장, 위치 방식 선택, 취소 |
| 위치 선택 | 거래 등록 | 선택적 위치 결정 | 현재 위치, 검색, 지도, 미리보기 | 위치 확정, 변경, 제거 |
| 거래 내역 | 하단 내역 | 목록 탐색 | 필터, 합계, 거래 목록 | 필터, 상세, 수정, 삭제 |
| 거래 상세 및 수정 | 내역 항목 | 거래 확인 및 변경 | 전체 거래와 위치 | 수정, 삭제, 지도 보기 |
| 지도 | 하단 지도 | 위치 소비 탐색 | 필터, Marker, Cluster, 기간 합계 | 이동, 확대, Marker 선택 |
| 지도 Bottom Sheet | Marker 선택 | 장소 소비 상세 | 장소, 합계, 건수, 최근 거래 | 거래 상세 이동, 닫기 |
| 통계 | 하단 통계 | 소비 분석 | 요약, 카테고리, 장소, 지역, 월 비교 | 기간 및 카테고리 변경 |
| 설정 | 홈 또는 프로필 | 개인 설정 및 데이터 관리 | 계정, 시간대, 카테고리 | 설정 변경, 탈퇴 |

### 10.3 거래 등록 단계

- 기본 흐름은 단일 화면에서 완료한다.
- 필수 필드는 거래 유형, 금액, 카테고리, 거래일이다.
- 선택 필드는 메모와 위치다.
- 위치 선택은 별도 화면 또는 Bottom Sheet로 열리며 완료 후 거래 입력으로 돌아온다.
- 위치 관련 실패로 기본 거래 입력값이 초기화되어서는 안 된다.

### 10.4 공통 상태

- Loading: 화면 전체를 가리지 않는 Skeleton 또는 진행 표시를 사용하고 중복 제출을 막는다.
- Empty: 데이터가 없다는 사실, 적용된 조건, 가능한 다음 행동을 함께 보여준다.
- Error: 사용자 행동으로 해결 가능한 오류와 시스템 오류를 구분하고 재시도 또는 대체 경로를 제공한다.
- 권한 거부: 브라우저 설정 안내와 함께 장소 검색, 지도 선택, 위치 없이 계속하기를 제공한다.
- 지도 키 미설정: 개발 환경에서는 설정 누락을 명확히 표시하고 거래의 비지도 기능은 유지한다.

## 13. 가정 제약 위험

### 13.1 가정

- 주요 사용자는 대한민국에서 KRW로 개인 거래를 기록한다.
- 한 계정의 거래는 초기 수년 동안 10,000건 이하인 개인 사용 규모다.
- 사용자는 위치 저장 여부를 거래마다 직접 결정한다.
- Kakao Maps 정책과 브라우저 Geolocation 정책을 준수할 수 있다.

### 13.2 제약

- Geolocation은 HTTPS와 사용자 권한이 필요하며 브라우저와 기기에 따라 정확도가 다르다.
- Kakao Maps API Key에는 허용 도메인 설정이 필요하고 호출량 및 정책 제한이 존재할 수 있다.
- PostGIS를 사용하지 않는 초기 구조에서 복잡한 반경, 다각형, 행정 경계 질의는 제한된다.
- 주소와 장소명은 외부 제공 결과의 스냅샷이므로 실제 정보 변경과 시차가 생길 수 있다.

### 13.3 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 위치 권한 거부율이 높음 | 위치 데이터 부족 | 위치 입력을 선택으로 유지하고 검색과 지도 선택을 제공 |

2. 사용자, 인증, 거래, 카테고리, 장소, 거래 위치의 관계와 삭제 전파 규칙을 ERD로 정의한다.
3. 금액 타입, 거래일 DATE, UTC 기록 시각, 사용자 시간대의 DB 및 API 표현을 확정한다.
4. Kakao 장소 ID가 있는 위치와 좌표 스냅샷 위치를 구분하는 데이터 모델을 정의한다.
5. 시군구 코드와 주소 스냅샷을 생성하는 위치 입력 및 주소 변환 흐름을 정의한다.
6. 거래 CRUD, 카테고리, 지도 영역 조회, 통계, 인증 API의 요청, 응답, 오류 코드를 작성한다.
7. 지도 조회의 Bounding Box 조건, 페이지 또는 결과 상한, 인덱스 전략을 정의한다.
8. Marker와 Cluster 책임을 서버와 클라이언트 사이에서 구분한다.
9. 승인된 Access Token 및 회전형 Refresh Token 쿠키 방식의 수명, 갱신, 로그아웃 즉시 무효화, CORS, CSRF, 로그 마스킹 정책을 구체화한다.
10. 정상, Loading, Empty, Error, 권한 거부, 지도 키 미설정 상태를 화면별로 설계한다.
11. 각 FR 및 NFR을 검증할 테스트 케이스 ID와 requirement-test-matrix.md 연결 규칙을 정의한다.
