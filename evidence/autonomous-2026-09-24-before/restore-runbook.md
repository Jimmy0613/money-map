# 복원 후보 생성과 접근 차단

2026-09-24 구현 범위: **로컬 격리 복원 후보 생성·재삭제·세션 폐기와 복원 모드 API 차단**. 운영 배포 승인이나 최신 ledger 증명을 대신하지 않는다.

## 도구의 경계

`scripts/restore-public.py`는 신뢰할 수 있는 `pg_dump -Fc --schema=public` 백업과 별도로 확보한 ledger JSON을 받아 **항상 새 PostgreSQL17.6 컨테이너**를 만든다. 기존 DB를 대상으로 받거나 초기화하는 옵션은 없다. 네트워크는 `none`, 공개 포트와 호스트 디렉터리 마운트는 없다. 사용자 DB에는 연결하지 않는다.

ledger JSON은 `[{"user_id":"UUID","deleted_at":"시간대 포함 ISO 시각"}]` 형식이다. 다른 필드는 거부한다. 입력 파일 해시를 별도 확보한 SHA256과 비교한 뒤 public만 복원하고, 별도의 privacy 스키마에 ledger를 적재한다. 기록된 사용자 재삭제, 관련 행 고아 검사, 전체 인증 세션·refresh token 폐기를 한 트랜잭션으로 수행한다. 실패한 새 후보만 정리하며 기존 DB와 입력 파일은 보존한다. 오류 SQL/행/입력값은 터미널에 출력하지 않는다.

호출 형식:

```sh
python3 scripts/restore-public.py --archive /보안경로/public.dump --ledger /보안경로/latest-ledger.json --ledger-sha256 별도로확보한SHA256
```

**해시 일치는 무결성 검사일 뿐 최신성 증명이 아니다.** 정상 처리 결과도 `releaseAllowed:false`이고 후보의 네트워크를 열지 않는다. 오래된 ledger에 올바른 해시를 제공해도 공개 허용으로 바뀌지 않는다. 입력·출력에 실제 개인정보가 포함된다면 운영 측의 암호화 저장·접근 통제·보존 정책이 필요하며 이 도구가 이를 자동 인증하지 않는다.

## 서비스 차단

복원 후보를 사용하는 Backend는 **반드시 `APP_RECOVERY_REQUIRED=true`**로 시작한다. 이 모드에서는 로그인·refresh·개인 API·readiness를 503 `RECOVERY_REQUIRED`로 차단하고 liveness만 허용한다. 이 값은 DB 외부의 배포 설정으로 유지해야 한다. 정상 신규 개발 환경의 기본값은 false이므로, 임의로 복원한 DB를 기존 환경 설정으로 시작하는 우회까지 자동 감지하는 장치는 아니다. 운영 배포 자동화에서 필수 설정과 네트워크 차단을 강제하는 작업이 남아 있다.

도구에는 공개 전환 명령이 없다. 다음을 운영 환경에서 입증하기 전 후보를 서비스에 연결하거나 차단 값을 해제하면 안 된다.

1. 서비스 중지 및 삭제를 포함한 쓰기 중단, 독립 저장소/WAL을 통한 최신 확정 deletion commit 복구·검증.
2. public 백업과 독립적인 privacy 보전, 백업·WAL 암호화 및 최대30일 보존 정책.
3. 해당 최신 ledger로 후보 재생성, 재삭제·고아 검사·세션 폐기 결과 재확인.
4. 외부 접근 차단 및 재개 절차를 운영 환경에서 훈련하고 결과 기록.

ledger 정리는 모든 관련 백업/WAL 복원 지점 만료를 증명한 뒤에만 허용한다. 이 도구는 ledger를 정리하지 않는다.

## 이번 훈련

`python3 scripts/test-restore.py`는 새 컨테이너와 합성 사용자만 사용한다. 탈퇴 전 public 백업→탈퇴 후 ledger→새 후보 복원에서 삭제 계정/관련 행 제거, 남은 계정 보존, 세션 폐기, 공개 포트 없음, 오래된 ledger의 공개 불허를 확인했다. 테스트가 소유한 새 컨테이너와 임시 합성 파일만 정리한다. 결과는 `evidence/review-restore-test.log`에 있다. 운영 저장소의 최신성·WAL·암호화·30일 만료는 미검증이다.
