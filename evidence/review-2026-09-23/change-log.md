- 승인 근거: 사용자 메시지 "기본값 전체를 승인합니다."
- 기존 내용: requirements.md 14절의 9개 기본값은 사용자 확인 필요 상태였으며 인증, 통화, 시간대 관련 설계에 승인 대기가 남아 있었다.
- 발견된 문제: 사용자 승인 이후에도 기존 미확정 표현을 유지하면 다음 단계가 승인된 결정을 재질문하거나 가정으로 처리할 수 있다.

## CHG-002 설계 구체화와 요구사항 충돌

- 일자: 2026-09-15
- 요청: 03 설계 프롬프트를 읽고 수행.
- 산출물: architecture.md, erd.md, api-spec.md 신규 작성. requirements.md와 승인된 CHG-001은 변경하지 않았다.
- 설계 결정: 단일 Spring Boot와 PostgreSQL, 동일 Origin 프록시, 5분 Access JWT와 14일 회전 Refresh, DB 세션 확인을 통한 즉시 무효화, 사용자별 복합 FK, 금액 문자열 JSON, revision 커서와 생성 멱등성, 클라이언트 SDK 주소 해석 및 Cluster, BBox 반환 상한, Vitest/RTL/MSW/Playwright 테스트 전략을 구체화했다.
- 이유: 승인된 요구사항을 코드, Migration 및 테스트로 옮길 수 있도록 기술 계약을 고정한다. 새로운 제품 기능은 추가하지 않는다.
- 영향: 인증 API 및 auth_sessions/refresh_tokens, 거래 API 및 operation_keys, 전체 소유권 FK, 지도 및 통계 조회, 화면 상태, 보안·금액·날짜·동시성 테스트.

### 충돌 A 위치 정확도 문구

- 기존 내용: BR-009에 "정확도가 1,000m보다 낮은 경우"가 있지만 승인된 14절은 "정확도 1,000m 초과 시 경고"다.
- 적용: 승인된 명확한 수치 기준 accuracyM>1000을 설계에 적용했다. 1000은 경고 대상이 아니다.
- 사용자 결정: 추가 승인 불필요. 이미 승인된 기준을 적용한 해석이며 원문은 보존했다.

### 충돌 B 오프라인 로그아웃

- 기존 내용: FR-003은 로그아웃 서버 요청 실패에도 클라이언트 인증 정보를 제거하고, 이전 인증으로 접근할 수 없어야 한다고 요구한다. CHG-001은 HttpOnly 쿠키를 승인했다.
- 문제: JS는 HttpOnly 쿠키를 지울 수 없고 네트워크가 끊기면 서버 세션 폐기도 수행할 수 없다.
- 변경안: 성공한 서버 로그아웃은 즉시 폐기 및 쿠키 만료를 보장한다. 실패하면 개인 화면과 자동 갱신을 차단하고 cache를 비우며 logoutPending과 재시도를 제공한다. 서버 확인 전에는 로그아웃 성공으로 보고하지 않는다.
- 영향: FR-003 예외 및 완료 조건, 인증 UI, /auth/logout, 오프라인·응답 유실 테스트. DB 구조 변경은 없다.
- 당시 상태: 요구사항 예외 문구 변경은 확인 필요로 남겼으며 원본 요구사항을 변경하지 않았다. 이후 CHG-003에서 사용자 승인으로 확정했다.

### 검증 범위

- Markdown 내용과 파일 인코딩, API JSON 예시, 요구사항 ID 매핑을 문서 수준으로 확인한다.
- 실제 SQL/Migration, 빌드, 애플리케이션, 성능 및 외부 연동은 미검증. SKIPPED - Windows 문서 작업 모드.

- 일자: 2026-09-15
- 승인 근거: 로그아웃 예외 규칙 확정 질문에 대한 사용자 응답 "네 그렇게 확정해도 됩니다."

- 변경 파일: requirements.md의 FR-003 처리 규칙·예외·완료 조건, architecture.md 결정 상태, api-spec.md 로그아웃 계약 및 상태.
- 영향: 인증 UI, POST /api/v1/auth/logout, 통신 실패·응답 유실·재시도·이전 토큰 거부 테스트. DB 모델과 Endpoint 경로 변경 없음.
- 사용자 결정 필요 여부: 없음. CHG-002 충돌 B의 승인 대기를 해소했다.
- 검증: 문서 간 승인 상태와 예외 규칙의 일관성을 확인한다. 구현·실행 테스트는 SKIPPED - Windows 문서 작업 모드.
