# 맥북 구현 인계

## 현재 위치

요구사항 분석, 설계, 승인된 기본값 및 로그아웃 예외, 설계 교차 검토 보완이 문서에 반영되어 있다. 실제 애플리케이션, Migration, 의존성 설치, DB, 빌드, 실행 테스트는 미수행이다. Windows 환경 점검 판정은 SKIPPED - Windows 문서 작업 모드이며 PASS가 아니다.

## 전달할 문서

정확한 파일명과 전달 후 확인 항목은 mac-transfer-files.md를 따른다. 원본 DOCX 6개와 Markdown 9개, 총 15개를 동일 프로젝트 폴더에 전달한다. 이 문서는 실제 파일 전송 또는 맥북 수신 확인을 의미하지 않는다.

- requirements.md: 기능 및 품질 기준
- architecture.md: 구성·보안·상태 전이·운영·테스트 전략, 11절 교차 검토 보완 포함
- erd.md: 데이터 타입·제약·Migration 및 11절 추가 데이터 계약
- api-spec.md: Endpoint·예시·검증·실패 복구, 11절 보완 포함
- change-log.md: 승인과 설계 변경 근거
- implementation-checklist.md: 단계별 작업 순서와 완료 조건
- requirement-test-matrix.md: 71개 계획 사례 및 합성 fixture
- 이 mac-handoff.md
- 01 사전 전제, 04 코딩, 05 테스트, 06 사전 샌드박스 테스트 DOCX. 02/03도 원문 근거로 함께 보관한다.

## 재개 순서

1. 맥북에서 실제 프로젝트 폴더를 열고 위 문서를 읽을 수 있는지 확인한다. Windows 절대 경로를 macOS 경로로 추측 치환하지 않는다.
2. 01 사전 전제와 06 프롬프트에 따라 읽기·쓰기·실행 권한, Java/Node/Wrapper/Docker·포트·Git 상태를 실제로 확인한다. Secret 값은 출력하지 않는다.
3. environment-check.md에 PASS/CONDITIONAL PASS/FAIL 및 근거를 기록한다. 현재 문서가 있다는 사실은 도구나 권한 검증 성공을 의미하지 않는다.
4. 04 코딩 프롬프트 및 implementation-checklist.md I-01부터 진행한다. 새 제품 결정이 없다면 기존 승인 항목을 다시 묻지 않는다.
5. 05 테스트 프롬프트를 읽고 추적표에 실제 수행한 테스트 증거를 기록한다. 아직 실행하지 않은 사례는 NOT_RUN을 유지한다.

FAIL이면 구현을 시작하지 않는다. CONDITIONAL PASS이면 확인된 제한의 영향을 받지 않는 작업만 진행한다. 이전 Windows 경로 E:\study\money-map은 출발지 기록일 뿐이며 맥북 실행 경로가 아니다.

## 추가 작업 검토 결과 (2026-09-15)

승인 상태, 설계 보완 기록, 구현 체크리스트, 테스트 계획과 전달 파일의 존재를 검토했다. 현재 문서에서 구현 착수 전에 추가 승인이 필요한 제품 결정은 발견되지 않았다. Windows에서 반드시 선행해야 할 문서 작업은 이번 전달 목록 작성으로 정리되었다. 이는 설계 무결성이나 실행 성공의 보증이 아니며, 구현 중 발견되는 문제는 기존 승인 범위에서 검토하고 보완한다.

- 환경 권한·도구 버전·의존성 호환성: 맥북의 06 환경 점검 및 I-01에서 실제 확인한다.
- 지역 사전의 실제 출처·버전·특수 행정구역: I-02에서 검증한다. 테스트용 합성 사전을 운영 자료로 사용하지 않는다.
- 실제 Kakao 연동·모바일 확인: 필요한 계정과 키가 준비된 후 검증한다. Mock 통과와 구분한다.
- 운영 백업·최신 ledger 복원: 배포 환경에서 격리 검증하며, 최신성을 입증하지 못하면 서비스 접근을 열지 않는다.

위 작업은 현재 Windows에서 실행하지 않는다. 추가 문서를 계속 늘리기보다 맥북 환경 확인을 다음 단계로 삼는다.

## 재승인 없이 유지할 결정과 안전 규칙

- CHG-001의 9개 기본값과 CHG-003의 로그아웃 실패 예외는 승인 완료다. 상세 근거는 change-log.md를 읽는다.
- CHG-004의 로그아웃 대기 지속성, 탈퇴 ledger 원자성·복원, 지출 전용 상세 필터, 변경 응답 유실 복구, 지역 정규화 계약을 구현에 반영한다.
- FR-027은 Could이며 MVP 필수 기능으로 임의 승격하지 않는다. CHG-005 이후 인계 기록도 함께 읽는다.
- 일반적인 검토·보완은 승인된 범위에서 진행한다. 제품 범위 변경, 계정·권한 승인, 불가역 작업은 필요한 시점에 사용자에게 확인한다.
- 파일은 UTF-8, BOM 없이 작성하고 문자열은 유니코드 이스케이프 대신 직접 표기한다.
- 기존 파일·변경을 보존한다. 실제 Secret, 쿠키, 사용자 데이터를 출력하지 않으며 DB 초기화나 파일 삭제를 기본 절차에 포함하지 않는다.
- 원본 프롬프트와 최신 승인 문서를 함께 읽는다. 과거 미확정 표현은 후속 승인 기록으로 해소되었는지 확인하고, 새로운 충돌을 임의로 요구사항 변경으로 해결하지 않는다.

## 준비 사항과 필요한 시점

| 항목 | 필요한 시점 | 사용자 작업 | Agent 작업 | 차단 범위 |
|---|---|---|---|---|
| 맥북 프로젝트 폴더 | 구현 시작 | 폴더 열기·문서 전달 | 실제 루트 및 권한 확인 | 구현 전체 |
| OS/Docker 권한 | 환경 점검에서 필요할 때 | OS 인증·권한 승인 | 미설치/접근 불가 사유 확인 | 해당 도구 실행 |
| Kakao 앱과 공개키 | 실제 지도 연동 전 | 앱 생성·키 발급·허용 도메인 등록 | NEXT_PUBLIC_KAKAO_MAP_APP_KEY 연결·Mock/실제 검증 구분 | 실제 지도 연동만 |
| 비공개 Secret | Backend 첫 실행 전 | 사용자가 관리하는 저장 수단 권한이 필요한 경우만 승인 | JWT_SECRET·CURSOR_SECRET·DB 비밀번호를 안전하게 구성하고 출력 금지 | Backend 실행 |
| 지역 자료 | 지역 통계 구현 전 | 현재 즉시 준비할 일 없음 | 공인 자료 출처·기준일·별칭을 확인하고 테스트용 사전과 구분 | 실제 지역 분류 검증 |
| 운영 호스트·도메인 | 배포 전 | 호스트·도메인 선택·계정 승인 | HTTPS·백업·복원·허용 Origin 구성 | 실제 배포 |

키 미설정은 거래 기록·API·Mock 테스트 구현을 차단하지 않는다. 실제 .env를 대화에 붙여 넣거나 문서에 Secret을 적지 않는다. NEXT_PUBLIC 키 변경은 재빌드가 필요하다는 기존 설계 계약을 따른다.
